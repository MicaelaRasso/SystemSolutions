# Corrección de la creación y programación de solicitudes y visitas

## Objetivo

Que el administrador pueda crear, editar, reprogramar, cancelar, reabrir y dar seguimiento a solicitudes de servicio («consultas») y visitas de servicio («turnos») sin errores, y que el árbol vuelva a compilar.

## Problema

El cliente informó dificultades para crear consultas y turnos. La auditoría de 2026-11-12 (lectura de código más `typecheck`, `lint`, `test` y `build`) encontró:

- El build está roto por un merge mal resuelto sin commitear en `src/components/portal/certificados-cliente.tsx:147-212`. Rompe `typecheck`, el build de `/portal/certificados` y su suite de tests.
- Diez defectos en el flujo `tarea-form` → `guardarSolicitudYVisita` (`src/lib/hooks/queries.ts:192`) → `service-workflow` → RPC. Están detallados en cada tarea.

## Alcance y restricciones

- Solo el flujo de solicitudes y visitas del administrador, más el arreglo del build.
- La solicitud de turnos desde el portal del cliente (RF-36) queda fuera: está prevista para marzo de 2027 y la decisión es de producto.
- Cambios SQL en migraciones nuevas y aditivas. No se editan migraciones ya aplicadas.
- Sin ramas ni commits salvo pedido explícito del usuario. Esta regla del usuario prevalece sobre los commits por unidad de trabajo de ODD.
- `supabase db push` remoto y la publicación de funciones quedan a decisión del usuario.
- Test primero cuando haya un runner aplicable: vitest para el front, `supabase/tests/*.sql` para SQL y `index.test.ts` para la edge function.
